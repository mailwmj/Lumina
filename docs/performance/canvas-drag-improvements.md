# 节点拖动连续性与快照计算优化

## 问题与方案

原节点对齐会在每次位置变化时，向全画布同级节点的边缘或中心线吸附；阈值为 12 个画布单位，关闭网格仍生效。输入横坐标从 88 连续增加到 112 时，节点可能一直停在 100，之后突然跳出；另一节点即使位于屏幕外很远处，也能触发这一行为。

现在拖动过程中直接使用鼠标产生的位置。仅单节点松手时，向同一父级、未隐藏且边界间距不超过 160 个屏幕像素的节点对齐，每个方向的修正不超过 6 个屏幕像素。阈值按缩放换算，开启网格时以网格为准；多节点拖动、程序设置的位置不参与对齐。最后一次对齐使用原有拖动结束的 Store 更新，因此与整段拖动共享一个撤销检查点，不增加额外保存或历史步骤。

原外部 Agent Hook 在 React 渲染阶段构建整图快照和 revision，即使连接关闭也照常计算。现在渲染阶段只保留输入引用，合并变化 100ms 后在实际发送时构建快照；没有变化的心跳复用缓存。持续变化期间仍保留既有五秒心跳，心跳需要发送新数据时会构建一次最新快照，避免长时间拖动导致连接失去更新。关闭连接时不构建快照、图片预览，也不轮询托管服务状态。外部变更和动作仍在执行时根据当前 Store 重新校验 revision，不使用发送缓存作写入校验。

## 验证结果

- `npm run build` 通过，包含 TypeScript 编译与生产构建。现有大包、动态导入和 Browserslist 提示仍存在。
- `npx vitest run`：81 个文件、400 项测试通过。
- 新增回归覆盖：连续拖动逐点跟随、远处和隐藏节点不吸附、不同缩放下的对齐阈值、网格优先、程序移动、多选、拖动和松手对齐的一次撤销/重做。
- Agent 回归覆盖：关闭时不构建快照和预览、拖动合并后发送最终位置、心跳缓存、关闭时取消待发送工作、重新开启发送最新数据、切换项目时只发送最新项目。既有直接应用和过期版本拒绝测试通过。
- 实际 Canvas 浏览器检查：50、100、300 节点各连续检查 60 个鼠标位置，全部跟随；Agent 关闭时拖动期间快照构建次数均为 0，无关节点内容的重渲染次数均为 0。松手对齐、撤销/重做、屏幕外远处节点、网格与多选检查通过，无浏览器运行错误。

原始结果：[canvas-drag-check.json](./canvas-drag-check.json)。复现命令：

```bash
node scripts/canvas-drag-check.mjs
```

脚本沿用现有基准的 Canvas 页面，在独立 Chromium 上下文使用合成节点和图片，不读取用户项目，不连接模型或外部 Agent。快照调用计数由测试服务器临时插桩，生产代码不包含计数器。

本次 50/100/300 节点的帧间隔 P95 分别约为 16.8/16.7/16.7ms。浏览器受约 60Hz 的采样频率限制，不能据此声称帧率提高；验证重点是位置连续性及移除不必要的计算。未验证真实 Tauri WebKit、大图解码、视频播放与高刷新率显示器场景。
