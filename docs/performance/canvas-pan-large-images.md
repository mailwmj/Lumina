# 多节点、大图与多选画布平移验证

日期：2026-09-10。源码基线：`d4bd4d4`，本次未提交改动在此基础上验证。

## 问题与修复

1. `Canvas` 订阅完整 viewport，平移每次更新都会重渲染主控制组件。现在只订阅主组件实际需要的 zoom；外部 Agent 桥接独立订阅 viewport，禁用时不响应视口更新。画布 Store 中的实时 viewport 仍照常更新。
2. 多选连线控件逐帧扫描节点 DOM 并读取选中节点及端口的布局。现在复用 React Flow 缓存的绝对坐标、尺寸与端口位置，通过 `ViewportPortal` 随画布变换；按钮保持 32px 屏幕尺寸。
3. 选中图片的尺寸标签曾创建原图 `Image`，仅为读取宽高就加载完整图片；节点移出、移回视口时还会重复。分镜图片的悬浮信息存在同样路径。现在通过应用服务共享元数据请求，由 Rust 后台读取本地图片文件头，无需解码整张图片；缓存最多保留 256 个来源的尺寸，不保留像素。
4. 图片加载完成但鼠标未悬停时，不再测量布局或更新悬浮提示。

只读检查安装版最近保存的项目：21 个节点，其中 17 个图片结果节点均已有最长边 1024px、约 150–330KB 的预览图；部分原图约 13–20MB。因此已有预览图仍可能被尺寸标签的原图加载路径绕过。检查未修改用户项目或资产。

## 验收标准与结果

- 平移不触发主 Canvas 重渲染、不改写节点和历史；多选不因平移丢失。
- 90 次平移输入的布局读取低于 500 次，不随多选数量成倍增长。
- 20–30MB 原图在多选和视口移出／移回时，不因尺寸标签创建原图 Image。
- 多选按钮在缩放和平移后仍正确定位，取消与无效目标不产生连线，合法目标一次连接所有来源。
- 本地元数据读取不依赖完整像素数据；文件缺失时正常降级。

WebKit 26.6，1440×1000，设备像素比 2，Vite 开发环境，80 个图片节点，缩放 0.4，90 次实际鼠标平移更新：

| 指标 | 修改前，选中 20 个 | 修改后，选中 20 个 | 修改前，选中 40 个 | 修改后，选中 40 个 |
| --- | ---: | ---: | ---: | ---: |
| Canvas 重渲染次数 | 90 | 0 | 90 | 0 |
| getBoundingClientRect 次数 | 5010 | 132 | 9689 | 132 |
| 节点／历史更新次数 | 0／0 | 0／0 | 0／0 | 0／0 |

50 与 300 个混合节点场景均为 0 次 Canvas 重渲染、102 次布局读取。视口裁剪正常生效，这两个场景的测量终点均有 8 个挂载节点；图片场景终点有 48 个挂载节点。

大图检查采用同一张 3000×2500 随机 PNG 的 20 个选中实例：Chromium 编码约 25.8MB，WebKit 约 26.2MB。两种引擎均未额外给 Image 分配原图来源。此检查验证浏览器加载行为；真正的本地文件读取由 Rust 测试独立验证。

多选连线检查覆盖 0.4 和 1 倍缩放、平移后右侧居中与 32px 点击区、双来源预览、pointercancel、注释节点拒绝连接、双来源成功连接图片节点。

## 结论边界

这些计数证实高频 React 更新、DOM 测量及隐式原图加载被消除，不能等同于安装版恒定 60fps。WebKit 的 40 个选中图片场景帧间隔 P95 仍约 30ms；开发构建、自动化调度、浏览器与系统合成开销均会影响帧时间。

安装版是 0.2.53，当前源码标记为 0.2.32。本次未替换安装包，修复尚未在用户安装版生效，也未对该安装包完成真实项目的帧率验收。

尺寸读取失败或来源为 HTTP(S)、data、blob 时，尺寸标签降级为文件名；不为非必要元数据下载或解码整张原图。原图查看与导出仍使用既有图片路径。
