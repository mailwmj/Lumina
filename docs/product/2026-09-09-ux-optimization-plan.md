# Lumina 用户体验诊断与优化方案

## 1. 目标与诊断边界

面向使用图片、视频、提示词和分镜进行创作的人，优先缩短「找到项目 → 进入画布 → 开始创作」路径，并使键盘操作、等待反馈和空状态清楚可见。

依据：当前源码、领域文档、既有视觉规范，以及本地 Vite 页面实际截图。当前仓库是 Tauri 桌面版；浏览器预览不能验证 SQLite、原生文件选择和供应商任务。现有 projectStore 持久化改动及其测试属于已有工作，不纳入此次修改。

## 2. 诊断结果

| 优先级 | 观察与证据 | 用户影响 | 方案 |
| --- | --- | --- | --- |
| P1 | ProjectManager 项目卡为只有 onClick 的 div；操作按钮 opacity-0，仅 group-hover 显示 | 无法用键盘进入项目；触控用户难以发现管理操作 | 卡片主体使用真实按钮，管理操作作为兄弟按钮；常显轻量操作，完整焦点反馈 |
| P1 | 项目页没有搜索，默认按创建日期排序 | 项目积累后，恢复近期创作需要逐个扫描 | 按更新时间倒序默认排列，增加名称搜索、结果计数、无结果与清空入口 |
| P1 | 空项目页要求“点击上方”，空画布只提示双击，中文界面副标题为英文 | 起步入口脱离阅读位置，依赖用户知道隐藏手势 | 空项目页直接提供创建按钮；空画布提供“添加节点”，复用既有创建菜单 |
| P1 | 打开项目仅显示 pointer-events-none 的浅遮罩；失败只进日志 | 点击是否生效不明确，失败后缺少可见解释 | 按钮禁用及明确打开状态；在界面层呈现打开失败与重试入口 |
| P1 | UiModal 缺少 dialog 语义、焦点约束、统一 Escape 与关闭后焦点恢复 | 键盘可误入背景；关闭方式随弹窗变化 | 为通用弹窗统一语义、焦点循环、Escape 与触发点恢复；输入法确认期间不提交项目名称 |
| P2 | 项目标题、两个排序器、两项动作挤在一行，缺少可换行策略；卡片日期同等强调 | 小窗口拥挤，用户难以快速识别项目与主要动作 | 标题与操作分区，搜索/排序独立工具行；项目名优先，节点数与更新时间辅助 |
| P2 | App hydration 返回全空背景；空画布辅助文字额外 opacity-60 | 等待时像未启动，说明难读 | 启动状态提供文字反馈，空状态使用现有正文和次级文本 token |
| P2 | NodeSelectionMenu 直接使用点击坐标定位，没有边缘约束与 Escape 关闭 | 靠近边缘或小窗口时菜单裁切；键盘添加节点缺少焦点落点 | 菜单限制在画布内，打开后聚焦首项，Escape 关闭 |
| P2 | 实际长名称走查发现 TitleBar 文本换行并挤出右侧操作；浅色菜单图标直接使用黄绿色 | 标题溢出固定高度，设置入口不可见；图标对比不足 | 标题单行省略并保留完整提示，操作区不压缩；菜单图标使用正文色 |
| P2 | SettingsDialog 独立实现大型弹窗；供应商设置与保存反馈需完整原生流程走查 | 设置行为与通用弹窗可能不一致 | 后续专项：配置有效性、未保存离开、保存/连接反馈、原生任务失败恢复；本次不改变配置保存语义 |

## 3. 视觉方向

领域关键词：素材、提示词、分镜、节点、连线、生成结果、创作项目。对应实体工作台中的炭黑背景、锌灰框架、纸白内容、石墨文字、黄绿色操作标记、紫色关系线。

保留 Lumina 的特征：内容为主的节点工作台，黄绿色只标记主要动作，紫色仍专属连接关系。项目入口用「项目名 + 节点数 + 更新时间」帮助恢复创作，不引入依赖读取完整项目的缩略图。

替换三个常见默认处理：用可直接执行的空状态替换孤立图标和说明；用搜索与最近编辑顺序替换只按创建时间的卡片墙；用轻边框和明确文字层级替换卡片悬停时的大阴影。

组件实施约束：沿用 Geist/中文系统字体及现有灰阶、surface、border token；以 4px 为间距基础；常规操作 32–40px 高；卡片/弹窗以现有 8–10px 圆角、轻边框分层。桌面紧凑但允许工具行换行，窄视口验证不作为新增移动端产品承诺。

## 4. 本次实施顺序

1. 项目页：搜索、默认最近编辑、信息层级、可访问卡片、可见管理入口、空状态、打开状态和失败恢复。
2. 通用弹窗：对话框语义、焦点管理、Escape、滚动和小视口约束；项目命名输入法保护。
3. 画布与启动：复用现有节点菜单提供显式起步入口；统一中英文空状态与启动反馈。
4. 验证后将结果记录到本文件。

## 5. 验收标准

- 名称搜索忽略首尾空格与大小写；无结果可清空；排序仍可切换。
- 键盘可进入项目并访问重命名、删除；管理按钮不触发打开。
- 打开期间有文字反馈，失败可重试；不更改持久化/API 契约。
- 弹窗有可访问名称，Tab 不进入背景，Escape 关闭后焦点回到触发点；中文输入法确认不误提交。
- 空画布单击“添加节点”打开原有注册表菜单；创建及双击路径继续可用。
- 中英文、深浅主题、桌面及窄视口无本次引入的明显重叠、裁切、未翻译键。
- 针对上述交互运行必要回归测试，完成 TypeScript 检查与前端完整构建；原生及付费生成未实际执行时明确标注。

## 6. 验证记录

本次实施已完成，包含第 4 节及实际走查追加的节点菜单边界、浅色图标和长标题处理。

### 6.1 自动验证

- `tsc --noEmit` 通过；最后一次 `npm run build` 包含 TypeScript 检查与 Vite 生产构建，均通过。
- 6 个测试文件、12 项测试通过：ProjectManager、RenameDialog、UiModal、NodeSelectionMenu、projectOpenPaneClickGuard、SettingsDialog。覆盖搜索/清空、默认排序、管理与打开动作隔离、等待/失败重试、输入法确认、焦点循环/恢复、下拉菜单优先关闭及创建菜单焦点/Escape。
- 测试命令使用 `TAURI_DEV_HOST=127.0.0.1 npx vitest run <上述文件>`，绕过当前环境的 localhost DNS 解析失败。
- 本次涉及的 18 个界面翻译键在中英语言包均存在；`git diff --check` 通过。
- 额外运行 nodeRegistry.test.ts 时发现既有失败：测试期待 8 项菜单，当前实现返回 6 项（音视频上传已合并入口）。在从 HEAD 导出的独立临时副本中复现同一断言失败，确认不是本次修改引入。本次没有更改注册表或放宽该断言。
- 构建仍提示主 bundle 较大、Browserslist 数据旧及既有动态/静态导入混用；这些问题未纳入本次界面修改。

### 6.2 实际界面验证

- 本地浏览器完成创建项目 → 空画布 → 添加节点 → 选择文本节点 → 返回项目页。
- 搜索无结果、清空恢复、键盘 Enter 打开项目、打开失败提示均经过实际操作。浏览器缺少 Tauri 后端，因此打开失败用于验证异常反馈，不代表已验证原生项目读取成功。
- 真实键盘验证重命名弹窗初始焦点、Tab 循环、Escape 关闭后恢复到重命名按钮。
- 菜单打开后焦点在首项，Escape 可关闭；390px 视口内的中心入口和右下角右键入口均完整显示。
- 实际查看中文深色、英文浅色/深色、中文浅色；检查 1280px 桌面、960×600 最小桌面窗口、390×844 窄视口；修复检查中发现的英文排序截断和长项目标题溢出。
- 样例项目仅用于浏览器内存中的界面走查，未写入原生项目数据库。
